# Kotlin

Kotlin — это современный язык программирования, разработанный компанией JetBrains (та самая компания, которая также занимается разработкой классных сред разработки - inteliji idea, py charm и так далее).

Kotlin создавался как более безопасная и лаконичная альтернатива Java, полностью совместимая с ней.

Kotlin отличается простотой синтаксиса, поддержкой функционального программирования, улучшенной безопасностью при работе с null и хорошей интеграцией с Java-кодом.

Язык достаточно молодой, разрабатывается с 2010 года, первые версии появились в 2011 году, а первый релиз был в 2016 году. 
Основные места применения – Android-разработка и Backend (да, бывает и такое, kotlin совместим с Java, а на Java нередко пишут и бэк).

В 2019 году Google объявил, что Kotlin – основной язык для разработки под Android.

## Kotlin и Java

Kotlin и Java – языки, которые идут в паре, их можно использовать в одном проекте.

Схема следующая:

И Kotlin, и Java компилируются в набор `.class` файлов компилятором kotlin и java соответственно, из которых в дальнейшем собирается `.jar`-файл.

Совместимость - полная, классы из Java можно использовать в Kotlin, классы из Kotlin можно использовать в Java.

За счет этого мы и можем работать со старым кодом Android SDK, написанном на Java.

## Функции и переменные

Начнем с функций и переменных. 

Что делает функция? Обойдемся без серьезного определения, функция принимает параметры и в зависимости от них возвращает результат и/или выполняет какие либо действия. Функция может и не принимать параметры, такие функции иногда еще называют процедурами.

Чтобы создать функцию, необходимо использовать ключевое слово `fun`.

```kotlin
fun max(a: Int, b: Int): Int {
    if (a > b) {
        return a
    } else {
        return b
    }
}
```

Объявление функции обязательно должно содержать ключевое слово `fun`, название функции, набор параметров (конечно, может быть и пустым, но скобочки все равно должны присутствовать), тип возвращаемого значения и блок кода. Значение возвращается с помощью ключевого слова return. Опционально может быть указан тип возвращаемого значения.

Давайте попробуем упростить наш пример и посмотрим, что еще умеют функции в Kotlin.

```kotlin
fun max(a: Int, b: Int): Int {
    return if (a > b) a else b
}
```

Касательно этого примера: в этом случае на самом деле важно еще сказать, что в Kotlin есть особенность, которая позволяет вынести весь код в одну строчку, поскольку `if` – выражение, а в той же Java – `if` – не выражение, он не возвращает результат.

Но делали мы это, чтобы посмотреть на интересные моменты синтаксиса Kotlin.

## = в функциях

Если наша функция должна возвращать результат и в целом укладывается в одну строку или конструкцию, мы можем воспользоваться следующим синтаксисом Kotlin-а:

```kotlin
fun max(a: Int, b: Int): Int = if (a > b) a else b
```

Или же, мы можем вообще опустить явное указание типа возвращаемого значения. В таком случае kotlin compiler вычислит его сам.

```kotlin
fun max(a: Int, b: Int) = if (a > b) a else b
```

## Возвращаемое значение – Unit

Что будет, если возвращаемое значение не указано? В обычном случае вернется `object Unit`. (`return Unit`)

```kotlin
fun writeToConsole() {
    print("Hello, world!")
}

// То же, что и:

fun writeToConsole(): Unit {

```

## Параметры функции по умолчанию и именованые параметры

В Kotlin у функций есть параметры по умолчанию, без чего очень тяжело в Java и что очень актуально для Android:

```kotlin
fun defaultParams(
    a: String,
    b: String = "2",
    c: String = "3",
) { ... }
```

Но чтобы параметрами по умолчанию было удобно пользоваться, в Kotlin также присутствует и механика именных параметров:

```kotlin
defaultParams("param a", "param b", "param c")
defaultParams(a = "param a", c = "param c", b = "param b")
```

В целом это означает, что во-первых, мы можем задавать параметры в любом порядке, если будем указывать их имя (что, конечно, не самое важное), а во-вторых, за счет этого мы вообще можем пользоваться параметрами по умолчанию:

```kotlin
defaultParams(
    a = "param a",
    // пропустили b 
    c = "param c",
)
```

В целом, тот же самый вызов можно записать и так:

```kotlin
defaultParams(
    "param a", // a – не именованый
    // пропустили b
    c = "param c",
)
```

Чего я конечно делать не рекомендую, в идеале – если в вызове встречается хоть один именованый параметр, следует именовать и все остальные.

Когда полезно:
- Параметры по умолчанию, уже рассмотрели
- Boolean-параметры

### vararg

В kotlin, как и в Java, есть поддержка vararg параметров.

Vararg в Kotlin — это способ передать переменное количество аргументов в функцию.

Когда мы добавляем модификатор vararg перед параметром, это значит, что в функцию можно передать любое количество значений этого типа, и они будут собраны в массив.

```kotlin
fun greetAll(vararg names: String) {
    for (name in names) {
        println("Hello, $name!")
    }
}
```

Несколько важных моментов:

- Только один vararg параметр на функцию, и он должен быть последним или перед последними с val name: Type по умолчанию.
- Можно передать уже готовый массив с помощью * (спред-оператор):

```kotlin
val array = arrayOf("Anna", "Oleg")
greetAll(*array)
```

- Внутри функции names — это обычный массив (В данном случае, `Array<String>`), и с ним можно работать как обычно.

## Типы

Бывает два вида типов:

Примитивы – это базовые типы: целое число (`Int`/`Long`), символ (`Char`), логическое значение правда или ложь (`Boolean`). _Хранятся в стеке._

Объекты же – "составные" типы, состоящие из примитивов и/или других объектов и обладающих поведением. Примером такого типа может служить `List` – список. _Хранятся в куче._

Главное отличие – примитивы передаются "по значению", а объекты – "по ссылке". То есть в переменной хранится сслыка на область в памяти, в которой уже находится набор других переменных (объектов, те опять же ссылок на объекты, либо примитивов). Одна из простых причин, чтобы мы банально не передавали параметрами между функциями целые потенциально огромные объекты (например, список из 1000 строк), а передали легкую ссылку.

Отдельных примитивных типов, как в Java и в других языках, в Kotlin нету, в Kotlin мы со всеми типами работаем как с объектами:

```kotlin
/**
 * Represents a 32-bit signed integer.
 * On the JVM, non-nullable values of this type are represented as values of the primitive type `int`.
 */
public class Int private constructor() : Number(), Comparable<Int> {
    ...
}
```

Пример с типом Int – 32-битным целочисленным числом.

## Примитивные типы

```kotlin
val boolTrue: Boolean = true
val number: Int = 1
val longNumber: Long = 1
val shortNumber: Short = 1
val byteNumber: Byte = 1
val doubleNumber: Double = 1.5
val floatNumber: Float = 1.5f
val charA = 'a'
```

Фактически, kotlin compiler преобразует все, что представлено выше, в примитивы. Это означает, что в переменной будет хранится не ссылка не объект, а именно значение. 

И да, в Kotlin присутствуют типы `Short` и `Byte`, но особого смысла использовать их нет, потому что:

- JVM всё равно преобразует их в Int при арифметике, потому что так  быстрее.
- К тому же меньше поддержки в стандартной библиотеке, чаще всё равно придётся приводить к Int.

Их стоит использовать только если реально важен размер — например, при работе с бинарными файлами или низкоуровневыми структурами – достаточно редкие случаи.

## Переменные

Переменные объявляются с помощью ключевого слова `val` или `var`.

- `val` (сокр. value, в других языках можно услышать про const или let) – объявление незименяемой переменной. 
При создании переменной мы указываем значение и не можем заменить его в дальнейшем.

- `var` (сокр. variable) – переменная, название в целом ее описывает. Сохраняемое значение, которое можно в любой момент заменить.

## Объявление переменных

Переменную можно инициализировать значением сразу, или позднее.

Типы можно явно не указывать при объявлении переменной, если она инициализируется сразу.

```kotlin
// Одно и то же
val a: Int = 1
val b = 1

// В данном случае же тип не указывать нельзя
val c: Int
c = 1
```

Читать переменную до инициализации конечно же нельзя, иначе произойдет ошибка компиляции.

Но опять же, тут вступает в игру наличие примитивов и переменных.

В kotlin переменные хранят внутри себя какое-то значение: примитивное (число, char, boolean,...), или же ссылку на объект.

В случае примитивов:

```kotlin
var a = 0
var b = a

a = 3

assert(b == 0)
```

В случае объектов и их модификации:

```kotlin
val list1 = mutableListOf(1, 2, 3) // Создаем объект List<Int> и сохраняем ссылку на него в переменную list1
val list2 = list1 // Создаем переменную list2 и сохраняем в нее ссылку на объект List<Int>, созданный ранее

list1.add(4)

assert(list2 == listOf(1, 2, 3, 4))
```

Поэтому, `val` не говорит о том, что наш созданный список никак нельзя будет изменить, нельзя будет изменить ссылку на наш список, но вызывать у него методы, которые будут менять его внутреннее состояние – можно.

### Nullable-типы

Одна из киллер фич Kotlin. Nullable типы.

По сравнению в Java, в Kotlin у нас есть Nullable типы. В Java нуллабельным у нас может быть любой тип. 

В Kotlin мы можем явно указать, сможет ли переменная принимать значение `null` или нет.

Тип nullable, если после него стоит символ вопросительного знака:

```kotlin
val a: Int = 0 // `a` нельзя присвоить null
val b: Int? = null // а `b` – можно присвоить null
```

Иерархия следующая: `Any` -> `Any?`, `String -> String?`, ...

Ну и да, на самом деле абсолютно все в Kotlin наследуется не совсем от Any, а от Nullable Any (Any?).

## Возможности nullable-типов

NonNull-тип "наследуется" от Nullable-типа и обладает все тем же поведением, и это работает только в одну сторону. `Int?` нельзя передать параметром в функцию или сохранить в переменную, если требуется тип `Int`. `Int?` и `Int` – разные типы!!.

## Работа с nullable-типами

### Smartcast with if

Так или иначе, nullable тип нужно преобразовать к non null или сделать какой-то fallback:

```kotlin
fun calculateA(): Int? { ... }

fun doSmth(a: Int) { ... }

val a = calculateA()
if (a != null) {
    // a автоматически преобразован к Int
    doSmth(a)
} else {
    // ...
}
```

### Fallback with ?:

```kotlin
// или

val a = calculateA() ?: 0 // Тип Int, тк если calculateA() вернет null, выражение вернет fallback-значение 0.
doSmth(a)
```

Оператор `?:` подедрживает также выход из функции с помощью return или проброс исключения.

```kotlin
val a = calculateA() ?: throw IllegalStateException("Error message")
doSmth(a)
```

### Null check with ?.

Если нам необходимо у nullable-объекта вызвать какой-либо метод при условии, что объект не null, мы можем воспользоваться следущей конструкцией:

```kotlin
data class Item(
    val title: String,
    val subtitle: String,
)

val items: List<Item>? = loadItems()
val first: Item? = items?.get(0)
```

Если items == null, в first сразу будет записано null.

### Assert with !!

Можно принудительно кастить тип к NonNull

```kotlin
val items: List<Int>? = loadItems()

items!!.get(0)
```

Но это плохо. Поскольку если items из данного примера будет null, то программа крашнется.

### Nullable и примитивы

Примитивы Int, Char, и тд также могут быть Nullable, но в таком случае они будут представлены в виде объекта. 

## Условные операторы

Про `if` уже немного поговорили, это ветвление, которое к тому же умеет возвращать результат. 

Но у `if` есть еще одна особенность - он умеет кастить объект к определенному типу после проверки (как мы уже делали это с проверкой на null).

## when

`when` в Kotlin — это расширенная версия `switch` из Java и других языков, но более мощная и выразительная.

Во-первых, мы можем использовать when ровно также, как `if/else if/.../else` (в общем, для большого набора разных условий):

```kotlin
when {
    condition1 -> {}
    condition2 -> {}
    condition3 -> {}
}
```

Можно работать с конкретной переменной, также есть поддержка дополнительной ветки `else`, если ни одно из условий не выполнится:

```kotlin
when (a) {
    1 -> {}
    2 -> {}
    else -> {}
}
```

`when` позволяет нам удобно работать с enum: если мы объявили три значения enum, нам достаточно перебрать все три значения и можно не добавлять ветку else.

## Циклы

В kotlin есть стандартные циклы `while`, `do while`, `for` и, фишка Kotlin – `Ranges`.

С while и do while, в целом, все стандартно:

```kotlin
var condition: Boolean = ...

while (condition) {
    // do smth
}

// или

do {

} while (condition)
```

А вот `for` в Kotlin интересный (хотя я бы сказал грустный).

Цикл `for` работает только с диапозонами (Ranges) или Iterable, например:

```kotlin
val list = listOf(0, 1, 2, 3, 4)

for (i in 0..(list.size - 1)) {
    println(list[i])
}
```

`..` – промежуток, включающий и начало и конец. Мы можем использовать infix-функцию `until` для создания Range, в таком случае промежуток будет включать только начало и исключать конец.

```kotlin
val list = listOf(0, 1, 2, 3, 4)

for (i in 0 until list.size) {
    println(list[i])
}
```

В дальнейшем, при компиляции, все это будет преобразовано во что-то подобное:

```kotlin
var i: Int = 0
while (i < list.size) {
    println(list[i])
    i += 1
}
```

## Лямбда-выражения

Теперь поговорим про лямбда выражения, то есть они же "замыкания". В kotlin они сделаны очень хорошо. Что такое лямбда выражение? Это по сути класс, в который мы забрали как поля все, что мы принимаем как параметр и который имеет единственную функцию `invoke()`. 

Для чего нужно?

1. Отложенное исполнение операций

```kotlin
button.setOnClickListener({ view ->
    // do smth on click
})

// То же самое
button.setOnClickListener { view ->
    // do smth on click
}
```

То есть мы говорим, что хотим повесить определенный клик листенер на кнопку и мы какое то действие добавляем, которое будет выполняться при клике на кнопку, передаем "поведение" в виде класса.

2. Переиспользование операций

Также мы можем переиспользовать операции, то есть мы можем как-то задавать действия. Есть maxBy – задаем, как мы делаем какие-то действия. Если бы использовали не int, а какую-то сложную структуру данных, могли бы явно указать, как искать наибольшее значение (по какому параметру).

```kotlin
val largestNumber = listOf(10, 40, 5).maxBy { it }
val lastWord = listOf("Computer", "Code").maxBy { it }
```

```kotlin
val oldest = people.maxBy { human: Human ->
    human.age
}

val oldest = people.maxBy { human ->
    human.age
}

val oldest = people.maxBy { it.age }
```

Тип параметра и название – опциональная штука, но имя лучше все таки указывать, чтобы понимать, в каком контексте мы работаем.

На самом деле при работе с коллекциями, DSL и тому подобными штуками лямбды встречаются очень часто.

Последний лямбда параметр, передаваемый в функцию, можно вынести из скобок и поместить отдельно. Иногда это очень удобно (когда, к примеру, нужно навесить клик листенер), иногда – нет.

### Синтаксис

В общем виде тип лямбды (анонимной функции) указывается следующим образом:

`(Параметры) -> Возвращаемое значение`

```kotlin
val printLambda: (Int) -> Unit = { println(it) }
printLambda(1)
```

```kotlin
val printNullableLambda: ((Int) -> Unit)? = { println(it) } // Как безопасно вызвать nullable-лямбду?

printLambda(1)
```

### Что из себя представляют

Возьмем наш первый и простой пример:

```kotlin
button.setOnClickListener { view ->
    // do smth on click
}
```

На самом деле, наш пример – то же самое, что и это:

```kotlin
button.setOnClickListener(
    object : Function1<View, Unit> {
        override operator fun invoke(view: View) {
            // do something
        }
    }
)
```

## Классы и объекты

**Класс** определяет формат для однотипных сущностей. В общем случае класс имеет какие-то данные/свойства (поля) и определяет какое-то возможное поведение (методы).

**Объект** (инстанс, сущность класса) – конкретный представитель класса, созданный и живущий в рамках заданного классом контракта (каждый инстанс обладает заданными свойствами (полями) и поведением (методами)).

Простой пример класса – Human, он обладает свойствами (`name`, `weight`) и поведением (`sayName()`).

```kotlin
class Human {
    private val name: String
    private val weight: Int

    constructor(name: String, weight: Int) {
        this.name = name // this - обращаемся к инстансу класса
        this.weight = weight
    }

    fun sayName() {
        println("My name is $name")
    }
}

val human = Human(name = "Name", weight = 80)
human.sayName()
```

В примере мы создаем инстанс через конструктор (тут тоже конечно же работают именованые параметры и параметры по умолчанию).

В конце вызывается метод `sayName` (методом называется функция, объявленная внутри класса).

Если в целом говорить про ООП, то объекты это представители конкретных классов – у нас `human` – объект класса `Human`. То есть класс – некоторый контракт, в котором есть еще и состояния помимо самого контракта.

Классы в Kotlin на самом деле не сильно отличаются от Java, от плюсовых, за исключением того, что в Kotlin отказались от концепции конструктора класса как отдельной условной "функции", которая называется как класс. То есть тут мы пишем явно, что это конструктор, за исключением дефолтного.

В большинстве случаев отдельно прописывать конструктор нам не нужно. 

Во-первых, конструкторы бывают двух видов:

- **Первичный (primary) конструктор** – если есть, то обязательно должен быть вызван
- **Вторичный (secondary) конструктор** – "альтернативный" способ создания инстанса класса, может быть 0+ вторичных конструкторов.

```kotlin
class User1 {
    val _name: String

    constructor(name: String) { // <- первичный конструктор
        this.name = name // this - обращение к текущему инстансу класса
    }
    // Это валидное решение, тем не менее, kotlin будет подсвечивать, что первичный конструктор все таки должен находится рядом с объявлением функции.
}

class User2 constructor(name: String) { // kotlin позволяет объявить параметры первичного конструктора прямо месте объявления класса.
    val name: String = name
}

class User3(name: String) { // Более того, в таком случае нам даже не обязательно явно прописывать ключевое слово constructor, это все еще первичный конструктор
    val name: String = name
}

class User4(name: String) { // <- первичный конструктор 
    val name: String = name

    constructor(nameSurname: Pair<String, String>) : this(nameSurname.first()) // <- вторичный конструктор, может вызывать первичный или любой другой конструктор, если бы они тут были.
}

class User5(val name: String) // Идеальная ситуация. val name – одновременно и объявление поля name типа String, и параметр конструктора.
```

Лучше избегать использования нескольких конструкторов и обходится только primary.

Существуют также **блоки инициализации**. 

Создаются они просто: для этого есть ключевое слово init, в фигурных скобках можно описать, что нужно делать на инициализацию класса (выполнится сразу после вызова конструктора).

```kotlin
class Shape(rawColor: String) {
    val color: String

    init {
        println("Create color: $color")
        color = rawColor
    }
}
```

Можно воспринимать как дополнение к первичному конструктору.

### Поля

Поля в общем случае хранят состояние объекта

```kotlin
class User(val name: String) {
    var address: String = "unspecified"
        get(): String {
            println("Address was requested")
            return field
        }
        set(value: String) {
            println("Address was changed for name: $name : $field -> $value")
            field = value
        }
}
```

Если мы откатимся чуть назад, то `var` в контексте класса это не просто поле как в Java или c++, оно также содержит внутри себя getter и setter. 

Мы можем переопределить `getter` и `setter`. Конечно, обычно геттеры и сеттеры просто присваиваются, мы ничего там не печатаем, ничего не записываем, тем не менее, ситуации, когда необходимо переопределить их, присутствуют. Внутри геттера и сеттера доступен `field` – текущее значение поля. В случае сеттера это var, которое можно менять.

Если скомпилировать Kotlin-код в байт-код, а затем декомпилировать в Java (можно считать, что так мы избавимся от сахара котлина, мы увидим следующее):

```kotlin
class User(val name: String) {
    var address: String = "unspecified"
}
```

```java
public class User {
    private final String name;
    private String address = "unspecified";

    public User(String name) {
        this.name = name;
    }
    ...

    public String getName() {
        return name;
    }

    public String getAddress() {
        return address;
    }

    public void setAddress(String address) {
        this.address = address;
    }
}
```

Соответственно, ко всем kotlin-полям из Java мы будем обращаться через методы с префиксами get/set (для Boolean префиксом будет is).

### Абстрактные классы и интерфейсы: наследование и инкапсуляция

Абстрактный класс в Kotlin — это класс, который не может быть создан напрямую и может содержать незаконченные (`abstract`) методы, которые обязаны быть реализованы в подклассах. Используется для задания общей логики и структуры для наследников.

Посмотрим возможности Kotlin на базовом примере.

```kotlin
abstract class Animal(val weight: String) {
    abstract fun whatDoYouSay()
}

class Cat(weight: String) : Animal(weight) {
    override fun whatDoYouSay() {
        println("Meow, meow")
    }
}

class Dog(weight: String) : Animal(weight) {
    override fun whatDoYouSay() {
        println("Woof, woof")
    }
}
```

В этом примере у нас есть абстрактный класс `Animal`. Он содержит поле (`weight`, вес) и функцию без реализации (`whatDoYouSay`), помеченную модификатором `abstract`, которую мы обязаны определить, если будем наследоваться от него.

Мы не можем создать сущность такого класса, но можем унаследоваться от него, что мы и делаем в нашем примере с помощью `Cat : Animal`. В реализациях мы можем задать поведение методов. 

В абстрактном классе `Animal` у нас объявлен единственный конструктор, который мы обязательно должны вызвать из нашего наследника. Поэтому наследники также принимают параметр `weight` и передают его дальше.

Зачем это нужно? У нас есть обязательство, что данный тип имеет заданное поведение, при этом реализация поведения зависит от конкретной сущности. Два хороших, но разных примера – `List<T>` и паттерн стратегии.

`List<T>` из Kotlin – список любых элементов не ограниченный по размеру. Базово, у него есть две реализации – `ArrayList` и `LinkedList`. 
У `ArrayList` реализация основана на массивах, реализованых на уровне языка – это структуры для хранения набора элементов, заранее ограниченные по объему. 

Когда массив заполняется, он просто пересоздается с большим размером под капотом.

`LinkedList` же – связанный список, каждый элемент обернут в сущность `Entry` и имеет ссылку на следующую `Entry`. 
Это более простая реализация, которая не тратит ресурсы на пересоздание массива, но при этом операция получения элемента по идексу более тяжелая, если оценивать сложность алгоритма – O(n) вместо O(1) у `ArrayList`.

Помимо этого, есть куча написанных методов, которым не важно, какая реализация списка у нас используется. Например, какой-нибудь супер-базовый `printList`, который выводит список в консоль особым образом. 
Он просто будет принимать параметром тип `List` вместо конкретной реализации, при этом спокойно использовать итератор для прохода по списку.

Эта особенность, возможность использования базового типа называется **полиморфизм**.

**Полиморфизм** – способность программы идентично использовать объекты с одинаковым интерфейсом без информации о конкретном типе этого объекта. 

Еще один пример – стратегия. Возьмем к примеру `RatingBar`. От фичи к фиче могут быть разные сценарии использования рейтинг-бара, кому-то, к примеру, нужно покрасить только целые, заполненные звезды, а кто-то хочет видеть точное отображение рейтинга. 

В этом случае у нас объявлен `RatingBarFillStrategy` с методами `calculateFilledAreaPx(params)`, а конкретная фича просто передает нужную реализацию этой стратегии в компонент.

```kotlin
interface FillStrategy {
    fun calculateFilledAreaWidthPx(
        rating: Float,
        ...
    ): Int

    class AsIs : FillStrategy {
        override fun calculateFilledAreaWidthPx(
            rating: Float,
            ...
        ): Int = ...
    }

    class IntegerStars : FillStrategy {
        override fun calculateFilledAreaWidthPx(
            rating: Float,
            ...
        ): Int = filledStars * starSizePx + filledStars * gapPx
    }
}
```

Только во-первых, тут у нас не класс, а интерфейс, это в целом похожее понятие, но определяет она исключительно поведение и не может описывать состояние.

Обычно говорят, что тип не наследует интерфейс, а **реализует** интерфейс. 

В данном случае стратегия AsIs реализует интерфейс FillStrategy.

И тут мы переходим к еще одному полезному примеру использования механизма наследования – общее поведение (интерфейсы) и сокрытие реализации.

**Интерфейс** — это контракт, который определяет набор методов и свойств, без хранения состояния. Классы могут реализовывать несколько интерфейсов, а интерфейсы могут содержать реализацию по умолчанию.

Каждый класс **может наследоваться только от одного класса**, но при этом **от неограниченного количества интерфейсов**. Такое ограничение наложено по следующим причинам:

Абстрактный класс позволяет хранить состояние (поля). Не должно быть умысла совмещать состояние двух разных типов данных в одном, в противном случае мы получим "супер-объект". Такого не должно существовать по расширенным принципам ООП и в правильной архитектуре, что будет рассмотрено подробнее в лекции по архитектуре. Сразу скажу, это принцип Single responsibility – принцип единой ответственности, наш класс не должен быть ответственным более чем за одну область.

### open/final

Обсудили, что у нас есть абстрактные классы и интерфейсы, от которых можно наследоваться. Стоит сказать еще пару слов про классы и наследование.

Конечно, мы можем наследоваться не только от абстрактных классов, но и от обычных, при условии, что они не являются `final`.

Класс может быть либо `final`, что означает, что от этого класса нельзя унаследоваться, либо `open`, что, соответственно, позволяет от него наследоваться.
Но важно понимать, что помимо этого свойство открытости присутствует у каждого метода класса.

В Kotlin нет ключевого слова `final`, но есть `open`. Каждый класс и метод, не помеченный модификатором `open` является `final` соответственно от него нельзя наследоваться/нельзя его переопределить.

## Any

В kotlin все классы наследуются от типа `Any`.

Это наследование неявное, мы нигде этого не указываем, но всякий раз, когда мы будем описывать класс, который не наследуется от какого-либо типа, **он будет наследоваться от `Any`**.

В Java каждый тип также наследуется, но уже от типа Object.

Any обладает тремя методами:

- `equals`
- `hashCode`
- `toString`

У Java `Object` методов больше, но в kotlin решили их убрать. В Java в методах класса `Object` был большой упор на многопоточность, но потребность в них по мере обновлений языка пропала.

Разберемся с методами `Any`:

- **equals** – метод, который сравнивает, равен ли текущий инстанс с другим инстансом, переданным аргументом.
- **hashCode** – метод, который считает hash-функцию от объекта и считает какое-то число. Это удобно использовать при сравнении объектов и в структурах данных, но бывают коллизии, о которых мы еще потом поговорим
- **toString** – метод, который приводит объект к строке, это нужно обычно для вывода текстового представления объекта в логах.

### Сравнение объектов

В kotlin есть оператор `==`, который:
- у объектов вызывает метод equals;
- примитивы сравнивает сразу по значению.

Как мы знаем, каждый объект в Kotlin является наследником `Any`, а значит каждый класс также в каком-либо виде реализует метод `equals`. 

В случае, **если метод не переопределен** ни в одном из наследников, **объекты будут сравниваться по ссылке** (если ссылки ведут на один и тот же инстанс (в куче), значит они равны, иначе – нет).

Мы также можем принудительно сравнить объекты по ссылке, даже если `equals` переопределен. Это можно сделать с помощью оператора `===`.

### Про hashCode

Можно дать следующее довольно абстрактное определение функции `hashCode`. 

Предположим, что x и y – некоторые объекты. 

Если `x == y`, то и `x.hashCode() == y.hashCode()`. Именно по такому принципу и должна строится реализация функции hashCode(). Никаких больше условий нет.

Какие выводы можно сделать из этого?

- Если `x.hashCode() != y.hashCode()`, то `x != y`, что прямо вытекает из определения.
- Если `x.hashCode() == y.hashCode()`, то это ничего не значит

Для чего нужен `hashCode`? Для ускорения. Посчитать числа гораздо проще, чем сравнивать все поля класса.

### Как реализовать equals

Оптимальная проверка равенства (реализация метода `equals`) выглядит следующим образом:

- Проверить объекты на равенство по ссылке с помощью `===`;
- Сравнение типов объектов, если они различаются, то объекты не равны;
- Сравнение hashCode, если они не равны, то объекты не равны;
- Сравнение каждого поля класса между собой.

Этот алгоритм нужно реализовывать руками в случае стандартного `class`. Однако, в настоящем коде встретить переопределение `equals` можно редко, поскольку в kotlin присутствуют `data class` – об этом немного позднее.

Пример переопределения `equals` и `hashCode`:

```kotlin
class User(
    val name: String,
    val surname: String,
) {
    override fun equals(other: Any?): Boolean {
        if (this === other) return true
        if (javaClass != other?.javaClass) return false

        other as User

        if (name != other.name) return false
        if (surname != other.surname) return false

        return true
    }

    override fun hashCode(): Int {
        var result = name.hashCode()
        result = 31 * result + surname.hashCode()
        return result
    }
}
```

В Java и Kotlin в методе `hashCode()` часто используется умножение на 31. Это связано с тем, что это число, обладающее рядом полезных свойств для эффективного расчёта хеш-кода.

- Умножение на 31 можно эффективно реализовать через сдвиг и вычитание: `31 * x == (x << 5) - x`;
- Простые числа, такие как 31, уменьшают шанс коллизий в хеш-таблицах. Особенно это важно при последовательной генерации хеша на основе нескольких полей.
- При переполнении 32-битного int "обрезается" лишнее (при переполнении 31 всё ещё даёт достаточно равномерное распределение остатков).

## data class

**data class** – один из видов классов в kotlin. Удобен тем, что при компиляции в классе **генерируются дополнительные методы**: `equals`, `hashCode`, `toString`, `copy` и `component1, ..., componentN`. 

Да, `equals`, `hashCode`, `toString` у нас итак существуют у каждого типа, так как все наследуется от Any. Но следует понимать, что в данном случае будут генерироваться именно **верные, полноценные реализации**, которые будут работать "из коробки" и зависеть от полей класса.

В случае обычного типа данных, если мы не переопределим, например, `equals` сами, то инстансы между собой будут сравниваться по ссылке.

Возьмем предидущий пример:

```kotlin
data class User(
    val name: String,
    val surname: String,
)

val user1 = User("Name 1", "Surname 1")
val user2 = User("Name 1", "Surname 1")

assert(user1 == user2) // если убрать модификатор data, то проверка не пройдет

// data class генерирует метод copy
val modifiedUser2 = user2.copy(surname = "Modified surname 2") 

println(user1.toString) // выведутся поля name и surname
```

Как было упомянуто, `data class` также автоматически создаёт методы `componentN()` для каждого свойства в порядке их объявления. Эти методы нужны для **деструктуризации объектов**.

```kotlin
data class User(val name: String, val age: Int)

val user = User("Alice", 30)
val (n, a) = user  // вызывает component1() и component2()
```

У `data class` также **есть ограничения**:
- такой класс обязательно должен содержать поля в конструкторе (иначе ему просто нечего будет генерировать);
- нельзя унаследоваться от `data class` (`data class` при этом может наследоваться). Это связано со сложностями генерации `equals`/`copy` из-за наследования.

`data class` очень удобно использовать для использования в структурах данных, для описания состояний экрана, например можем сравнивать состояния экрана, предидущее и новое.

## enum classs

**enum class** — это способ задать перечисление фиксированного набора значений, каждое из которых является объектом.

Инстансы `enum class`-а создаются только внутри скоупа `enum class` и более нигде, иными словами: при опредлелении enum сразу создаются все возможные описанные инстансы класса, больше эти экземпляры не могут ниоткуда взяться.

```kotlin
enum class Color {
    Red,
    Green,
    Blue,
}

enum class ColorWithCode(val hexCode: Int) {
    Red(0xff0000),
    Green(0x00ff00),
    Blue(0x0000ff),
}
```

`enum class` удобно использовать для описания заранее заданного ограниченного набора состояний:

```kotlin
enum class ButtonStyle {
    Primary,
    Secondary,
}

class Button() : ViewGroup {
    ...

    var style: ButtonStyle

    ...

    private fun resolveBackgroundColor(style: ButtonStyle) = when (style) {
        ButtonStyle.Primary -> context.getColor(R.attr.color_accent)
        ButtonStyle.Secondary -> context.getColor(R.attr.color_secondary)
    }
}
```

Во-первых, мы определяем человекопонятные названия состояний, а во вторых, мы можем удобно использовать `enum` в `when`. Если мы будем сопостовлять значение с типом enum в `when`, то придется либо описать все кейсы значения enum, либо добавлять дополнительный блок `else`.

Если мы опишем все значения, то обойдемся без `else`. 

Если мы добавим еще одно значение в `enum` и не поддержим его в `when`, проект не соберется.

## sealed class/interface

В kotlin есть абстрактные классы и интерфейсы, которые могут иметь ограниченное количество наследников. Это **sealed class/interface** (sealed от англ. запечатанный).

Это "расширение" концепции enum class-ов – зафиксированы все возможные наследники класса, но создать их можно в любом месте.

Наследники sealed class/interface могут располагаться только в том же пакете, что и sealed class/interface.

Посмотрим на примере:

```kotlin
sealed class Result

data class Loaded(val data: String) : Result()
data class Error(val e: Throwable) : Result()
object NotModified : Result()

fun printResult(result: Result) {
    when (result) {
        is Loaded -> println(result.data)
        is Error -> Log.e("Tag", result.e)
    }
}
```

В данном случае у нас объявлен `sealed class Result` (допустим, результат запроса в сеть) и объявлены все его наследники, больше – не будет. Это, как и enum, сразу в одном месте описывает (в контексте примера) все возможные результаты работы, но позволяет нам самим определять свойства и поведение каждого из наследников – если данные загрузились – у нас есть информация, если произошла ошибка – у нас есть возникшее исключение.

Что это нам дает:
- Удобная обработка результата с помощью when – после проверки на типы when умеет автокастить переменную к типу из проверки, из-за чего мы можем выводить данные из Loaded или логировать ошибку из Error без дополнительного приведения.:

```kotlin
when (result) {
    is Loaded -> {
        showContent(result.data) // Каст к Loaded
    }

    is Error -> {
        showError(result.e) // Каст к Error
        Log.e(e)
    }
}
```

- when в этом случае будет работать быстрее (оптимизация JVM, проверка на тип будет проходить быстрее за счет заранее известных всех наследников класса)
- Возвожность игнорирования else ветки
- Безопастность – невозможность наследования от данного класса вне пакета.

`sealed class/interface` повсеместо используются для описания состояний экранов, для каких то доменных моделей и тому подобных вещей. Вы сможете часто встретить их в коде.

## object

Существует паттерн – Singleton. Singleton – класс с единственной сущностью с единой точкой доступа из любого места кода.

Если реализовывать такое поведение самостоятельно, самый простой вариант будет выглядеть следующим образом:

```kotlin
val SINGLETON_INSTANCE = Singleton()

class Singleton private constructor() {
    fun doSomething() {
        println("Do some work")
    }
}

fun main() {
    SINGLETON_INSTANCE.doSomething()
}
```

`object` реализует singleton из коробки. У `object` существует единственная сущность класса, до которой мы имеем доступ из любой точки программы в рамках модификатора доступа.

```kotlin
object Singleton {
    fun doSomething() {
        println("Do some work")
    }
}

fun main() {
    Singleton.doSomething()
}
```

### const

В object поля могут быть помечены как `const`:

```kotlin
object GeoUtils {
    const val SUCCESS_CODE = 1

    fun doSomething(): Int {
        ...
        return SUCCESS_CODE
    }
}
```

В Kotlin const может использоваться только для переменных верхнего уровня или внутри object/companion object.

`const` будет работать как compile-time constant. Это значит, что чтение `const val` будет заменено на конкретное значение во всех местах.

В виду того что `const` – compile time constant, есть определенные ограничения, связанные с ее использованием:

- Значение должно быть известно на этапе компиляции.
- Неизменяемо (подходит только `val`).
- Тип – один из примитивных типов (Int, Double, Boolean, и т. д.) или String.

Почему нельзя использовать const внутри обычного class?

Потому что `const val` должна быть доступна без создания экземпляра. А поля внутри класса принадлежат экземпляру.

Объекты типа `object` — это синглтоны, создающиеся один раз, и они имеют поведение, аналогичное `static` (по сравнению с Java). Компилятор может гарантировать, что доступ к `const`-переменной возможен без создания экземпляра.

Это можно безопасно скомпилировать в Java-подобный `static final`.

### static

В прошлом подразделе обсудили, что в В Java есть ключевое слово `static`, которое позволяет объявлять поля и функции внутри класса, не относящиеся при этом к сущности класса. В kotlin такого механизма нет.

Это связано с тем, что `static` в Java вызывает некоторые проблемы, две основные:

- Он плохо вписывается в ООП. static-члены не могут быть переопределены, не участвуют в наследовании и т.п.
- `static` усложняет тестируемость. Статические функции хуже поддаются замене/мокингу в тестах.

### companion object

Тем не менее, kotlin дал возможность размещать константы и не привязанные к инстансу класса функции путем объявления `object` внутри класса с тем же именем. Такой `object` называется `companion`.

```kotlin
class ProductCardFragment() : Fragment {
    // Поля и методы ...

    companion object {
        const val ID_ARG_KEY = "id"
    }
}

// нам не нужно создавать сущность, чтобы получить это значение, оно доступно отовсюду.
ProductCardFragment.ID_ARG_KEY
```

## Внутренние и вложенные классы

В kotlin есть механизм вкладывания классов внутри другого класса со ссылкой на внешний класс (`inner`) и без (`nested`). 

`nested` класс – это просто класс, который мы определили внутри другого класса. Все, на что это влияет – зоны видимости этого класса (если мы используем модификатор доступа private, класс будет виден внутри верхнеуровневого) и способ обращения к классу (в примере – `RatingBar.FillStrategy`):

```kotlin
class RatingBar(...) : View(...) {
    ...

    interface FillStrategy {
        ...
    }
}

val fillStrategy: RatingBar.FillStrategy = RatingBar.FillStrategy.AsIs()
```

Все классы, создаваемые внутри других классов по умолчанию будут `nested`, ничего дополнительного указывать не нужно.

`inner class` же имеет ссылку на внешний класс, внутри которого он объявлен, и может обращаться к нему. Но создать инстанс можно только внутри внешнего класса.

```kotlin
class NetworkManager private constructor() {
    private var maxThreads: Int = 4
    ...

    inner class Builder() {
        fun setMaxThreads(maxThreads: Int): Builder {
            this@NetworkManager.maxThreads = maxThreads
            return this
        }

        ...
    }
}
```

`inner class` имеет доступ к приватным полям внешнего класса, поэтому его удобно использовать для билдеров.

В случае inner-класса нужно явно прописать, что создаем `inner` при объявлении класса.

## Пакеты

Пакеты (`packages`) позволяют сгруппировать файлы исходного кода.

Пакет файла может не совпадать с путем к файлу.

Можно определять функции и поля на уровне пакета. (При компиляции обернется в object).

С помощью `*` в импортах можно импортировать все классы пакета. Но обычно линтеры запрещают его использовать, чтобы не было конфликта наименований, если мы хотим импортировать, к примеру, своего `User`, а оказывается он уже подключен как раз путем `*,` хоть и не используется.

## Модификаторы доступа

Мы можем явно задавать, где мы сможем использовать наши:
- Классы, интерфейсы, object
- Конструкторы класса
- Поля (+ отдельно для get и set у var)
- Методы
- Функции и поля, объявленные в файле

Всего в kotlin существует 4 модификатора:

- `public` (по умолчанию, доступно везде)
- `internal` (доступно внутри модуля) – удобно для библиотек или для многомодульного проекта, где мало чем нужно делиться наружу.
- `protected` (доступно только в подклассхак-наследниках), нельзя использовать вне класса (нельзя использовать на уровне пакета).
- `private` (доступно только в том же классе/файле (в случае классов или функций/полей, объявленных в файле))

```kotlin
// Класс – internal, он будет доступен только в текущем модуле.
internal class NetworkManager {
    private var maxThreads: Int = 4 // Поле – приватное, будет доступно только внутри класса или inner класса

    // метод – публичный, но, поскольку класс internal, будет доступен также только внутри модуля
    fun doRequest(request: Request) { 
        prepare()
        ...
    }

    // метод – приватный, будет доступен только внутри класса или inner класса
    private fun prepare() {
        ...
    }
    ...
}
```

В Java был модификатор доступа по умолчанию `package private` (то есть класс/метод будет доступен только внутри того же пакета, где он объявлен). В kotlin от него отказались.

Чтобы наш класс/метод был доступен везде, нам не нужно явно прописывать public, хотя такая возможность есть. В kotlin-модуле можно включить `Explicit API Mode`, тогда везде явно придется прописывать public, это нужно для sdk и библиотек, чтобы случайно не оставить ничего публичным.

## Всякие полезности

### Extension

`Extension`-функции позволяют расширять функциональность класса, даже не имея доступа к нему.

```kotlin
fun User.fullName() = "$name $surname"

// or

val User.fullName
    get() = "$name $surname"
```

Эти функции позволяют добавлять функциональность в классы и интерфейсы, не модифицируя их.

Компилируются в обычные функции с добавленным параметром – объектом расширяемого класса. Если компилировать и декомпилировать код в Java, будет примерно следующее:

```java
// Сама extenstion-функция
// В kotlin: `fun User.fullName() = "$name $surname"`
class FileNameKt {
    public static String fullName(user: User) {
        return name + " " + surname;
    }
}

// Место вызова
// В kotlin было бы user.fullName()
final String userName = FileNameKt.fullName(user);
```

Мы видели, что с помощью extenstion можно сделать новое поле. На самом деле **это вообще не поле**, хотя выглядеть все будет именно так, это скомпилируется во что-то такое:

```java
// val User.fullName
//     get() = "$name $surname"
class FileNameKt {
    public static String getFullName(user: User) {
        return name + " " + surname;
    }
}

// Место вызова
// В kotlin было бы user.fullName
final String userName = FileNameKt.getFullName(user);
```

То есть, абсолютно то же самое, что и в прошлом примере, только называется это как getter. По факту обязанность хранить поле или вычислять его значение в таком случае ложиться на нас.

## Generic-типы

Generic позволяют использовать единую логику для разных типов объектов. Записываюся в треугольных сбоках: `<T>`.

Они могут определяться для всего класса, для конкретной функции или поля (дополнительный механизм абстракции).

Работают по принципу стирания типов (type erasure) – информация о generic-типе не хранится в скомпилированном коде: данные хранятся в виде Any, а в местах использования – приводятся к нужному типу. 

Исключение – inline-функции с reified-параметром.

`<*>` – может быть использован любой тип (Any).

Самое популярное место использования generic-ов – коллекции. Давайте на их примере и посмотрим.

## Коллекции

`List` – список элементов, не ограниченный по размеру. Он реализован следующим образом: в объявлении есть generic T, то есть список элементов определенных типов (`Int`, `Long`, `String`, `...`)

Реализован на Java и находится в пакете `java.util`. Есть две реализации:

- `ArrayList<T>` – реализация основана на массиве, который расширяется при заполнении. можно создать с помощью функций `arrayListOf`, `listOf`, `mutableListOf` или напрямую, вызовом конструктора `ArrayList()`.

- `LinkedList<T>` – связный список (linkedListOf)

`Set` – можестно элементов, похоже на список, но с важным нюансом: set может хранить только уникальные элементы. Если добавить некоторые `item1` и `item2` в пустой Set, при условии что `item1 == item2`, `set.size` будет равен 1.

Есть две реализации:

- `HashSet<T>` – сет, основанный на массиве и hashCode (позиция определяется за счет hashCode, поэтому элементы находятся в коллекции хаотично, а не в порядке добавления). Можно создать вызовом конструктора `HashSet()`.

- `LinkedHashSet<T>` – сет, отслежвающий порядок добавления. Можно создать с помощью функций `setOf`, `mutableSetOf` или с помощью вызова конструктора `LinkedHashSet<T>`.

generic в этом случае сработает следующим образом:

Допустим, мы создаем `List<Int>`. Информация о generic-типе Int не сохранится в скомпилированном коде: данные будут хранятся в виде Any, а в местах использования (например, при получении элемента списка через метод `get(...)`) – приводятся к нужному типу `Int`.

Интересный момент: из-за такой механики работы generic при работе с ними примитивы `Int`, `Char`, ... будут преобразованы к объекту.

Самая сложная тема про дженерики: сейчас попробуем ответить на вопрос, является ли `List<Int>` подтипом `List<Number>`? `Number` выше чем `Int` в иерархии, `Number` - надтип `Int`, `Int` – подтип `Number`. Дело в том, что в kotlin есть разные типы generic-ов:

`Generic<T>` – инвариантный generic

`Generic<out T>` – ковариантный

`Generic<in T>` – контрвариантный

`List<T>` объявлен инвариантным. Пройдемся по определениям и посмотрм:

Если тип Generic – **инвариантный**, то: B подтип A -> `Generic<B>` **не подтип** `Generic<A>`.

То есть, **`List<Int>` не подтип `List<Number>`**.

Тип Generic – **ковариантный**, если B подтип A -> `Generic<B>` **подтип** `Generic<A>`

Если бы `List<T>` был объявлен как `List<out T>`, то он бы считался **ковариантным** и `List<Int>` **был бы подтипом** `List<Number>`.

Тип Generic – котрвариантный, если B подтип A -> `Generic<A>` подтип `Generic<B>`.

Контрвариантность в Kotlin означает: "можно безопасно передавать значения типа T или его подтипов внутрь объекта", но нельзя читать из него значения типа T. Это полезно, когда объект только принимает значения, но не возвращает их — например, обработчики, логгеры.

С ин/контр/вариантным тяжело разобраться при первом знакомстве и встречаться они будут не часто. 

### HashMap

Еще одна структура данных – `HashMap`.

- Позволяет быстро получать значение по ключу. Быстро не по времени, а по алгоритмической сложности (в среднем работает за константу, потому что в среднем нам нужно только посчитать hashCode, а это просто посчитать циферку не сложно)

- hashCode ключа определяет бакет, где хранится значение

Внутри `HashMap` реализована на массиве. 
Чтобы понять какое значение нужно достать, нам нужно понять какой индекс нам нужен. 

`hashCode` ключа определяет бакет, то есть просто номер, для определения индекса с бакетом в массиве используется битовый сдвиг.

При возниковении коллизии в бакете формируется красно-черное дерево для простоты поиска нужного значения. Для поиска нужного значения в бакете применяется equals.

## Исключения

В Kotlin присутствует функционал исключений, который, в отличие от Java, работает только с unchecked (в Java есть checked исключения, которые необходимо обязательно проверять в коде, иначе программа не скомпилируется).

**Исключения** – указывают на появление нештатной ситуации. Они прерывают исполнение программы.

Вот к примеру мы парсим строку в double, а у нас неверный формат. Мы дальше ничего сделать не можем, потому что формат неверный, падаем. Но падать приложению – очень плохо.

Поэтому исключения но можно перехватить, обработать и продолжить выполнение с помощью **`try`/`catch`**.

Исключения выбрасываются с помощью оператора `throw`.

`try`/`catch`, как и `if`/`else` – выражение и возвращают значение, то есть можем сделать основанный на этом return.

В презентации представлена иерархия исключений, все идет от `Throwable` к `Exception` и `Error`. `Exception` и `Error` – разные виды исключений. `Error` – runtime исключение, которые сложно обработать (прим.: `OutOfMemory`, `StackOwerflow`).

```kotlin
try {
    val strings = list[5].toInt()
    ...
} catch (e: NumberFormatException) {
    // Ошибка формата числа
} catch (e: IndexOutOfBoundsException) {
    // Индекс вне диапазона списка
}
```

### finnaly

`finnaly` позволяет выполнить действие независимо от исключений. Чаще всего используется для очистки ресурсов.

```kotlin
val stream = inputFile.inputStream()

try {
    val text = stream.reader().readText()
    println(text)
} catch (e: IOException) {
    println(e.message)
} finally {
    stream.close()
}
```

## Аннотации

Аннотации добавляют Meta-информацию к коду. 

Она может быть как просто информативной, так и служить для какой-то задачи.

Например, аннотация `@Deprecated` помечает код, который в будущем будет убран, удален и его лучше не использовать.

С другой стороны:

Когда мы компилируем код, мы можем с помощью компиляторных плагинов врезаться в этот процесс, на каком-то из этапов поменять или сгенерировать код. И мы как раз по аннотациям можем найти все места, для которых нам нужно что-то сделать (сгенерировать/изменить код). Пример самый явный наверное будет уже в лекции по Compose, потому что сам по себе Kotlin таких аннотаций практически не провайдит (из kotlin есть пример `@JvmStatic`).

Помимо этого, информация может использоваться также и во время исполнения программы, через reflection api мы можем получить например все поля, классы с искомой аннотацией.

```kotlin
objects Utils {
    @JvmStatic
    fun sayHello() = println("Hello")
}

@Deprecated("use new fun")
fun oldFunction() {
    ...
}

class Repository @Inject constructor() {
    ...
}
```

### Рефлексия

Рефлексия – киллер фича JVM, но и боль. Код на Kotlin/Java исполняется на виртуальной машине и виртуальная машина знает о всех свойствах, методах, классах и тому подобных вещах, которые есть в программе. Это не очень надежно, так делать не нужно, но возможность такая есть.

Во время работы программы, мы буквально можем создать новый класс, получить доступ до private переменных, менять значение у val и тому подобные вещи.

```kotlin
class ClassToReflect {
    val timeCreated = System.currentTimeMillis()

    fun callMe(): String {
        return "Thank you for calling"
    }
}

fun main() {
    val obj = ClassToReflect()
    val kClass = obj - javaClass.kotlin
    println(kClass.members.joinToString { it.name })
    val prop = kClass.memberProperties.find { it.name == "timeCreated" }
    val method = kClass.memberFunctions.find { it.name == "callMe" }
    println("Reflected: timeCreated=${prop?.get(obj)} callMe=${method?.call(obj)}")
}
```
